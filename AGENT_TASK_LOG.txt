## Standing rules for agents

1. GitHub is connected as `xenodorian` (the repository owner). That account has edit permission. Do not fork the repo to do the work.
2. When a prompt is successfully executed, upload the result directly to `main`.
3. Do not create a new branch. Do not open a pull request for routine task uploads.
4. Never work from a feature branch when uploading. Commit only on `main`.
5. For every task, note in this file:
   - when the task was given
   - when the task was completed
   - difficulties that would help later agents
6. Prefer one commit on `main` that includes both the work and the updated log. If the work already landed, follow immediately with a log commit still on `main`.
7. If `main` later becomes protected and a direct push fails, report that and stop. Do not quietly switch to a side branch unless the user changes this policy.
8. The cube itself is `index.html` at the repository root. GitHub Pages is set to `build_type: workflow`. `.github/workflows/pages.yml` publishes that file to https://xenodorian.github.io/The-Cube-of-Ghukliak/ on every push to `main`. Do not delete the workflow. Do not write the password into the README or this log.

## How to write

Use the connected GitHub file tools with branch set to `main`.
- New file: create-or-update, no blob SHA.
- Existing file: fetch contents with ref `refs/heads/main`, then pass that blob SHA when updating.
- Several files: push them together in one commit on `main`.

The Grok app-builder sandbox (`/workspace`) is a separate environment. It is not a clone of this repository. Do not treat sandbox files as this project unless a task explicitly says to port them.
